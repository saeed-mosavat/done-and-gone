# Domain docs

This project uses a single-context layout:

- GLOSSARY.md at the repository root
- Architecture decision records under docs/adr/

Before exploring, read the glossary and relevant ADRs when present.
If absent, proceed silently; create them only when terms or decisions
are resolved through domain modeling.

Use glossary terms consistently in code, tests, issues, and documents.
Flag contradictions with existing ADRs rather than silently overriding them.
